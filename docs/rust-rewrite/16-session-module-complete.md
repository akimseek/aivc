## 2. 四处**必须做对**的地方

### 搜索的竞态：请求号

连续输入会连续触发请求，而**后发的可能先回**——先回的旧结果会盖掉新结果，界面显示的
就是上一次的搜索结果。

处理：一个自增请求号，只有最新那次的结果允许落地。

```ts
const seq = ++requestSeqRef.current;
const fresh = await api.searchSessions(...);
if (seq !== requestSeqRef.current) return;   // 过期结果直接丢掉
```

### 收藏：先改本地，失败回滚

收藏是**即时反馈**的操作。等一个 IPC 往返再更新，点击会显得没反应。

因此先改本地状态，再发请求；失败则**改回去**——否则界面会显示一个并不存在的状态。

### 批量还原只能逐条

后端**没有**批量还原命令（只有单条 `restore-session`），因此前端逐条发。

一条失败**不该让其余停下**：全部做完后如实报「成功 N 条、失败 M 条」，而不是整体回滚
——回滚会把已经成功的那几条也搞成不确定状态。

### 分页是**往前插**，不是追加

「加载更早的消息」取回的是更早的区间，必须插到数组**前面**：

```ts
setMessages((current) => [...page.messages, ...current]);
```

追加到末尾会让对话顺序整个乱掉。是否还有更早，由「当前起始序号 > 0」决定。
