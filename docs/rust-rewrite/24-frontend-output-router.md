# 24 · 把「接收端未就绪缓冲」抽出来并补上测试

计划里的第 2 步：前端组件与 hook 的测试覆盖。

**没有安装 jsdom 与 testing-library。** 与其为此引入两个重量级 devDependency，
不如先把那段逻辑**抽成纯单元**——这本来也是它该有的形状。

## 1. 为什么不是「装 jsdom 再测 hook」

被测试的目标是 `useTerminals` 里的一段逻辑：

```
push(terminalId, bytes):
  接收端在吗？在 → 直接送
              不在 → 缓冲，等 register 时按原顺序补发
```

它是**纯逻辑**：输入是「某个终端的输出与注册动作」，输出是「谁收到了什么、顺序如何」。
它此前长在 hook 里，用**三个并行的 Map ref** 表示（块列表、字节数、接收端），
同时承担「分发」「缓冲」「补发」「上限」「清理」五件事。

用 jsdom + `renderHook` 去测它，测的是 React 而不是这段逻辑；而抽成类之后，
**零新依赖**就能覆盖全部行为。这也和工程既有的做法一致（`session-display.ts`、
`command-palette.ts` 都是纯逻辑 + 测试）。

## 2. 抽取结果

新增 `ui/src/app/terminal-output.ts`：

| 成员 | 职责 |
| --- | --- |
| `push(id, bytes)` | 有接收端直接送；没有则缓冲（带上限） |
| `register(id, sink)` | 挂接收端并**按原顺序**补发缓冲 |
| `release(id)` | 卸载接收端 / 终端关闭：连同未发出的缓冲一起丢 |
| `pendingBytes(id)` / `hasSink(id)` | 诊断与测试 |

`use-terminals.ts` 只剩接线：一个 `useRef` 持有 router，回调转调它。
`TerminalSink` 类型搬到 `terminal-output.ts`，`use-terminals.ts` 继续
`export type { TerminalSink }` 转发，`terminal-pane.tsx` 改为直接从新模块导入。

**一个刻意的改动**：`closeTerminal` 此前只删接收端、**不清缓冲**；现在走
`release`，连缓冲一起丢。终端都没了，留着只是占内存。

## 3. 九条测试，每条对应一个会真实出错的场景

| 测试 | 挡住的故障 |
| --- | --- |
| 已挂上接收端时直接送达 | 基线 |
| 接收端还没挂上时先缓冲，挂上后补发 | **终端永远空着，直到用户敲一下键盘** |
| 补发时保持原来的块顺序 | 控制序列错乱、屏幕内容乱掉 |
| 补发之后不再重复发送 | 提示符显示两遍 |
| 不同终端互不串台 | 一个终端的提示符出现在另一个终端窗口里 |
| 超出上限时丢新的、保住旧的 | **把用户最需要看的那一行扔掉** |
| 卸载后新来的输出重新进入缓冲，而不是丢掉 | 标签切换后屏幕内容断掉 |
| 卸载时丢弃未发出的缓冲 | 内存随终端开关堆积 |
| 块列表与字节计数始终同步 | 计数与实况脱节，上限判断失效 |

「上限丢新的」这条值得单说：上限只防失控，而**提示符在开头**——丢新的才能保住用户
真正需要看到的开头。

## 4. 假绿检查

把 `push` 改回「没有接收端就直接丢弃」，9 条里**红了 7 条**：

```
× 接收端还没挂上时先缓冲，挂上后补发   expected +0 to be 8
× 补发时保持原来的块顺序               expected [] to have a length of 3 but got +0
× 补发之后不再重复发送                 expected 'twice' to be 'oncetwice'
…
```

断言确实承重，不是「写了就绿」。

## 5. 端到端回归（这次重构动的正是输出路径）

光有单元测试不够——重构的是**真实应用里每一条输出都要穿过的路**。所以重建二进制、
在真实应用里跑一遍：

```
输入前：{"prompt":"PS C:\\Users\\akim>  "}
输入后：{"tail":"PS C:\\Users\\akim> Write-Host aivc-router-probe\naivc-router-probe\nPS C:\\Users\\akim>  "}
```

**「输入前」那一条才是关键证据**：提示符是在**没有任何输入**的情况下出现的。
而 shell 的提示符正好打印在「终端已启动、接收端还没挂上」那个窗口里——
**它出现，就证明缓冲补发这条路径真的在跑**。如果退化成丢弃，这里会是空的。

「输入后」则证明接收端挂上之后是直送，两条路径都覆盖到了。
