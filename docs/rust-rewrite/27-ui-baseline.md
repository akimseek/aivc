# 27 · 界面基线集

新增 `scripts/ui-baseline.ps1`：**每个视图固定一张**，同一组步骤、同一个初始状态。

## 1. 为什么要和过程图分开

`shots/` 里那 29 张是**过程图**——每一次修 bug 留下的证据。它们能回答「当时为什么这么
改」，但回答不了「这次改动有没有把界面弄坏」。

基线集相反：**同一组步骤重跑一遍、逐张 diff**，就能看出界面回归——包括门禁和单元测试
都看不见的那些：排版错位、元素被挡、文案换了位置。

## 2. 与 `ui-check.ps1` 的分工

| 脚本 | 行为 |
| --- | --- |
| `ui-check.ps1` | 启动一次、拍一张，每次都从干净状态重来 |
| `ui-baseline.ps1` | **只启动一次**，多次附着同一个调试端口；状态在步骤之间累积 |

累积正是「浏览一遍各个视图」需要的行为：先看启动状态，再点开会话，再开终端，
再打开配置，最后压上退出确认框。

## 3. 五个视图

| 名称 | 拍到的 |
| --- | --- |
| `01-启动默认` | 应用启动后的样子 |
| `02-会话详情` | 点开第一行会话 |
| `03-终端` | 点「+ Shell」并等到 xterm 就绪 |
| `04-配置` | 点「配置」按钮 |
| `05-退出确认` | `app:command {quit}` 之后 |

每一步的 probe 都会打印**当时页面处于什么状态**（行数、条数标签、终端是否就绪、
配置的六个标签、退出框的三个按钮）。只看图有时分不清「没这个元素」和「图拍早了」，
这行诊断就是用来分辨的。

## 4. 两处踩到的坑

### 4.1 第一张的名字曾经是错的

它本来叫 `01-会话列表`。实测它与 `02-会话详情` **逐字节相同**
（SHA256 前 12 位都是 `3F5FC8EA13B3`，长度都是 215461 字节）。

原因：**应用会记住上次选中的会话**，启动时详情已经打开了，所以「点第一行」什么都没
改变。

已改名为 `01-启动默认`，并在脚本里写明原因。**名字要如实反映拍到了什么**——叫错了会让
后来看基线的人对着图找不存在的差异。

### 4.2 `.ps1` 必须带 UTF-8 BOM

第一次跑直接语法错误，报错里的中文全是乱码（`ui/dist 姣?aivc-app.exe`）——脚本被按旧
代码页读了，中文注释把字符串引号切断了。

**新建 `.ps1` 之后要补 BOM**（`write` 工具写的是不带 BOM 的 UTF-8）：

```powershell
$text = [System.IO.File]::ReadAllText($path, [System.Text.UTF8Encoding]::new($false))
[System.IO.File]::WriteAllText($path, $text, [System.Text.UTF8Encoding]::new($true))
```

改完再 `Parser::ParseFile` 查一遍语法，比跑起来才发现便宜。

### 4.3 又一次：**看文件，不看退出码**

文件头写明了理由，脚本里的判断也是这么写的：

```powershell
if (-not (Test-Path $out)) { $failed += $step.Name; ... }
```

因为 `cdp-shot.cjs` 在 CDP 连接断开时会**静默退出 0**——「退出码 0」在这里不代表成功。

## 5. 怎么用

```
./scripts/ui-baseline.ps1                              # 落到 shots/baseline/
./scripts/ui-baseline.ps1 -Name after-变更            # 落到 shots/after-变更/
```

然后逐张对比 `shots/baseline/` 与 `shots/after-变更/`。

> 脚本在 `ui/dist` 比 `aivc-app.exe` 新时会**拒绝运行**——Tauri 在编译时嵌入前端，
> 否则拍到的是旧界面。这条与 `ui-check.ps1` 一致。

## 6. 还差什么

- **没有自动 diff**：现在靠人看。要自动化需要引入图像比对依赖，而目前的判断是
  「五张图人眼看一遍」比引入依赖更划算。
- **配置面板只拍了第一个标签**（供应商）。其余五个标签没拍——那需要额外的点击步骤。
