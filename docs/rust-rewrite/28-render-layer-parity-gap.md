## 3. 为什么会跑偏

回头看，轨迹是：

1. 后端命令面接线（这一步是对的，也做完了）
2. 修「能力只接了一半」的 bug —— **有价值**，找到 7 个真缺陷
3. 但接着把**验证工具本身**当成了产出：CDP 截图、jsdom 装配测试、基线集
4. 然后开始做**边角语义**：条数下界 → 精确总数

第 2 步是必要的（那些 bug 让功能根本没生效）。第 3、4 步的问题是：
**它们优化的是「已经实现的那一小块的正确性」，而不是「把没实现的做出来」。**

而当时的判断依据是「门禁全绿 + 端到端通过」——**这个指标衡量不了覆盖率**。
L1–L20 里 11 条根本没实现，门禁当然不会红：它们连代码都没有。

> **教训**：验收矩阵（`03`）才是进度指标。`cargo test` 全绿只说明**已写的**是对的。
