# 29 · 界面重设计规范

> 用户决策（2026-09-26）：**在保持功能一致的前提下，重新设计一版更现代化的界面。**
>
> 依据是 [28](28-render-layer-parity-gap.md)：L1–L20 里有 11 条明确不满足。所以这一轮不是
> 「润色」，是**在保持矩阵要求的前提下重做视觉与信息层级**。

## 0. 一条边界，先说清楚

**信息架构按 L1–L20 保持一致，现代化体现在视觉语言与交互细节。**

通用设计建议里有一条「仪表盘不要总是左侧栏，试试顶部导航」——**这里不采用**。L1 与 L2
明确要求「菜单栏 / 侧栏 360px / 工作区 / 状态栏」与两级侧栏导航，那是**验收项**，不是
风格偏好。把它改掉就不是「功能一致」了。

「一致」的客观依据是矩阵；视觉怎么好看是另一回事，两者不要混。

## 1. 审计（对着 `ui/src/styles/tokens.css` 与文件面）

### 1.1 已经是对的

| 项 | 现状 |
| --- | --- |
| 强调色**只有一个** | `--ui-accent: #168c78`，饱和度 73%（< 80%，不刺眼） |
| 灰色族一致 | 全是冷灰（`#17212b` → `#93a0ad`），没有冷灰暖灰混用 |
| 阴影带色调 | `rgba(29, 45, 58, 0.12)`——冷色，不是纯黑低透明 |
| 背景不是纯白/纯黑 | `--ui-bg: #f4f6f8`、`--ui-surface: #ffffff` |
| token 分层 | `tokens.css` 独立于 `app.css` / `components.css`，改色不用全库搜字符串 |

**这套 token 是有设计意图的**，重设计应当**扩展**它，不是推倒。

### 1.2 要修的（按影响排序）

| # | 问题 | 证据 |
| :-: | --- | --- |
| 1 | **排版是无意的** | `font-family: Inter, ui-sans-serif, system-ui, …`（`tokens.css:47`）——但**没有任何东西提供 Inter**，实际渲染成 Segoe UI。写了等于没写 |
| 2 | **等宽字体绑死 Windows** | `Consolas, monospace`（两处）——跨平台会退化成浏览器默认 |
| 3 | **没有字号阶** | 各处直接写 `13px` / `15px`，没有 `--ui-text-sm/md/lg` 这类可调层 |
| 4 | **没有图标系统** | 新前端一个图标都没有；旧平台用 Lucide（L19 要求统一） |
| 5 | **没有圆角/间距/z-index 阶** | 逐处硬编码 |
| 6 | **`index.html` 缺 meta** | 只有 `<title>`，没有 `description`、没有 favicon |
| 7 | **数字用比例字体** | 条数、token、耗时都是比例数字，列不对齐 |
| 8 | **状态残缺** | 有 `EmptyState`，但**没有骨架屏**、没有 toast（旧平台有 `notice-toast`） |

### 1.3 一个必须解决的约束

**Tauri 应用运行时不联网**（`base: "./"`，自定义协议加载本地资源）。所以：

- **不能用 Google Fonts 之类的 CDN 字体**——装上就是个空白等待
- 要「有性格的字体」，只能**把 woff2 打进产物**（`@font-face` + Vite 相对路径）

**待定**（下一轮第一步就定）：

| 方案 | 代价 | 收益 |
| --- | --- | --- |
| A. 打包 **Geist** + **Geist Mono**（OFL 授权） | 约 100–200 KB | 界面有明确性格；等宽也统一 |
| B. 有意选择系统栈（`Segoe UI Variable` → `Segoe UI` → …） | 0 | 零体积；但 Windows 之外观感不稳 |

倾向 **A**：这是桌面应用，体积不敏感；而「现代化」很大一部分就是排版。

## 2. 视觉方向（三条主张）

1. **把「工具感」做实，不要玻璃拟态。** 这是一个终端 + 会话 + 网关的控制台，用户在里面
   待很久。毛玻璃、大圆角、彩色渐变会让它像营销页。方向是**精确、克制、信息密度高**：
   细边框、克制的层次、只在真正需要强调处用强调色。
2. **层次靠留白与分隔线，不靠卡片堆叠。** 现在大量「边框 + 白色 + 阴影」的卡片（通用
   设计里点名的「generic card look」）。改成**用间距与细分隔线分组**，只在浮层（对话框、
   下拉）上用阴影——那里的阴影真的在表达「浮在内容之上」。
3. **数字要对齐。** 条数、token、端口、耗时全部 `font-variant-numeric: tabular-nums` +
   等宽。这一条对一个控制台的价值远超任何装饰。

## 3. 设计系统扩展（在现有 token 上追加）

```css
/* 排版阶：所有字号只从这五档里取 */
--ui-text-xs: 11px;   /* 标签、徽章 */
--ui-text-sm: 12px;   /* 次要信息、表格 */
--ui-text-md: 13px;   /* 正文（当前默认） */
--ui-text-lg: 15px;   /* 标题 */
--ui-text-xl: 18px;   /* 面板大标题 */

/* 间距阶：4 的倍数，只从这里取 */
--ui-space-1: 4px;  --ui-space-2: 8px;  --ui-space-3: 12px;
--ui-space-4: 16px; --ui-space-5: 24px; --ui-space-6: 32px;

/* 圆角阶：内层更紧、外层更松（避免「所有东西同一个圆角」） */
--ui-radius-sm: 4px;   /* 输入框、按钮、标签 */
--ui-radius-md: 8px;   /* 面板、卡片 */
--ui-radius-lg: 12px;  /* 浮层 */

/* z-index 阶：取代散落的魔数 */
--ui-z-base: 0; --ui-z-sticky: 10; --ui-z-drawer: 40;
--ui-z-overlay: 60; --ui-z-toast: 80;

/* 等宽：终端与所有数字 */
--ui-font-mono: "Geist Mono", "Cascadia Mono", Consolas, monospace;
--ui-font-sans: "Geist", "Segoe UI Variable Text", "Segoe UI", system-ui, sans-serif;
```

**唯一强调色的用法约定**：强调色只用于「当前选中 / 主操作 / 焦点环」。等待确认用
`--ui-warn`、错误用 `--ui-danger`，三者不混用。

### 第 9 轮 · 一次**无效改动**，以及它暴露的方法问题

**做了什么**：为了修「另存到...被截断」，给 `.session-head` 加 `flex-wrap: wrap` +
按钮 `flex: 0 0 auto`。

**结果：图像与上一轮逐字节相同**（sha256 都是 `6ad9d25b1d…`）——**改动毫无效果**。
已撤回，不留「看起来在修但实际无效」的规则。

**它暴露了一个更要紧的问题**：我把「另存到...」判为截断，依据是**预览图**——
1920×1230 被缩到 999×640 后我看到的。而源码里那个标签是 `另存到…`（**一个省略号
字符**）。**在约一半缩放下一个 `…` 字形看起来就是三个点。**

→ **我很可能把「缩小后的省略号」误读成了「文字被截断」。**

**教训（两条，都关于方法）**：

1. **预览图能发现「看起来不对」，但判断「是不是缺陷」必须回到原尺寸或数据。**
   这一轮和上一轮（把会话真实的首条消息误判成渲染问题）是同一个错误的两种形态。
2. **改动无效时，「没效果」本身是信息**——它说明我对成因的假设是错的。此时
   正确动作是撤回并重新假设，**不是**保留一条无害但会误导后来人的规则。

### 第 8 轮 · 消息区用形态区分角色

**根因**：助手与用户**都是「浅色底 + 边框」的方块**——助手 `--ui-surface-subtle`
（#f8fafb）、用户 `--ui-surface`（纯白）。在纯白工作区上这两个几乎一样，整段对话读起来
是一堆同样的方块。

**改法**：**形态**而不是深浅。

| 角色 | 形态 | 含义 |
| --- | --- | --- |
| 助手 | **无框正文**，直接落在工作区上 | 它就是这一页的内容 |
| 用户 | **引述块**：强调色底 + 左侧 3px 竖线 + 右圆角 | 这是「我说的」 |

左侧竖线而不是整圈边框——引述是**引述**，不是卡片。引述块里的正文用 `--ui-text-soft`
而不是纯正文色，避免在强调色底上出现生硬的深色。

**实测**（`shots/after-messages/02-会话详情.png`）：助手消息变成直接落在工作区上的正文，
读起来像一份记录而不是一堆方块，噪音显著下降。

> ⚠️ **这一屏没有用户消息**，所以用户侧的引述块样式**没有在图上验证**。样式规则写了，
> 但「看起来对不对」还没看过。下次遇到含用户消息的会话时补验。

### 第 6 轮 · 两级导航用**形态**表达层级

**根因**：一级（会话/快捷/搜索）与二级（活跃/回收站）**用的是同一个 `ChipGroup`**，
不区分的话看上去一模一样——用户分不出「换一处地方」和「换一个筛选」。

**改法**（不动共享组件，只在侧栏内覆盖）：

| 层级 | 形态 | 含义 |
| --- | --- | --- |
| 一级 `.pane-nav` | **分段控件**：有底、有边、等宽、选中项整块高亮 | 「切换目的地」 |
| 二级 `.view-nav` | **文字标签**：无底无边，选中项只加下划线 | 「筛同一批内容」 |

**用形态而不是颜色深浅**表达层级：深浅只能说明「哪个更重要」，形态能说明「它们是什么
关系」。下划线留了透明占位，选中时不会把相邻项挤动。

**实测**（`shots/after-nav/02-会话详情.png`）：一级是带框的分段控件、「会话」整块高亮；
二级是文字标签、「活跃」带下划线。

**仍未做**：消息区无角色区分；「另存到...」被截断；以及第 2 批的功能缺失项。

### 第 5 轮 · 会话列表降噪

**改动**（`app.css` 的会话行四处）：

| 问题 | 改法 |
| --- | --- |
| 预览与标题**同深**，每行看起来都是两行正文 | 预览从 `--ui-muted` 退到 `--ui-faint`（**一档**）。内容不动——那是会话真实的首条消息，改它就是篡改数据 |
| 三段等距（`gap: 2px`）读成一块 | 间距分开给：标题↔预览紧（3px）、预览↔日期松（`margin-top`） |
| 标题靠继承拿颜色 | 显式给 `var(--ui-text)`。**标题要先被看到，不能靠碰运气** |
| 日期左右参差 | `font-variant-numeric: tabular-nums` |
| 悬停是「再深一点」 | 侧栏是浅灰底，悬停变白 = 浮起来，更符合直觉 |
| 写死的 `#cfe8e1` / `13px` / `11.5px` | 全部换成 token |
| `.star.on` 的金色 | **刻意保留的第二个色相**并写明理由：金色在极小面积上就能表达「已收藏」，换成强调色的青绿会被当成「已选中」 |

**实测**（`shots/after-rows/02-会话详情.png`）：预览明显退到标题之后，标题先跳出来，
列表整体安静了；选中行的强调色底在浅灰侧栏里很明确。

**仍未做**：一级导航（会话/快捷/搜索）与二级视图（活跃/回收站）仍是纯文字，没有主次
表达；消息区无角色区分；「另存到...」被截断。

### 第 4 轮 · 侧栏上半屏让位给会话列表

**改动**（CSS-only，一处）：`.field` 是 `display: grid; gap: 5px`——**标签一行、控件一行**，
于是平台/目标两个选择器吃掉侧栏上半屏。这两项**很少改**，却占了最贵的位置。

在 `.pickers` 里把 `.field` 覆盖成两列（标签贴文字宽度、下拉吃剩余空间），并给标签一个
`min-width: 2.5em` 让两个下拉的**左边缘对齐**。

**只覆盖 `.pickers` 以内的 `.field`**：配置面板里的表单保持上下堆叠——那里标签更长、
控件更复杂，横排反而挤。

**实测**（`shots/after-pickers/02-会话详情.png`）：两个选择器各占一行，左边缘对齐；
**会话列表多露出一行**（能看到 09-20 那条）。

**同时更正一条我上一轮的误判**：我把「会话列表项的预览是英文原文」列成了问题。
打开数据看，那是**会话的真实首条消息内容**（`stripMarkup` 之后的用户提示词），
不是渲染缺陷——**改它就是篡改数据**。

真实的问题只是它**与标题视觉权重相同**，让列表显得吵。改法是压暗、缩到一行，
而不是替换内容。

### 第 3 轮 · 视觉层次：让界面有一块「底」

**改动**（对照第 2 轮看图得到的清单）：

| 图上的问题 | 改法 |
| --- | --- |
| ① 侧栏与工作区**都是纯白**，整屏一张纸 | 侧栏改用 `--ui-surface-subtle` **后退一层**，内容留纯白。分区靠**底色差**，不再只靠一条细线 |
| ⑥ 滚动条是系统默认的深色粗条 | `::-webkit-scrollbar` 改成 10px 细条、半透明、悬停才显形 |
| — | 补 `:focus-visible` 焦点环（可访问性要求；用 `focus-visible` 而非 `focus`，鼠标点击不留环） |
| 技术债 | `.menubar` / `.sidebar` / `.sidebar-head` 里写死的 `#d9dee7`、`10px`、`18px` 全部换成 token |

**实测**（`shots/after-hierarchy/02-会话详情.png`）：侧栏与工作区已能一眼分开；会话列表
的选中项在浅灰底上是白色，**浮出来了**；右侧滚动条不再抢眼。

**仍然没改的**（下一轮）：
- ② 平台/目标两个大 select 仍占掉侧栏上半屏
- ③ 一级导航「会话/快捷/搜索」仍是三个文字按钮，没有分量
- ④ 会话列表项的预览是英文原文，两行且不可读
- ⑤ 消息区没有角色区分
- ⑦ 「另存到...」被截断

> **记一条方法**：这两轮的改动都是**看过图之后**才定的。第 2 轮我按文件面数组件得出
> 「菜单栏完全没有」，看图后发现有骨架——**文件面衡量不了「界面做没做」**。

### 第 1 轮 · 设计系统（token 阶 + 排版）

已完成：

| 项 | 内容 |
| --- | --- |
| 字号阶 | `--ui-text-xs/sm/md/lg/xl` + `--ui-leading-tight/leading` |
| 间距阶 | `--ui-space-1…6`（4 的倍数） |
| 圆角阶 | `--ui-radius-sm/md/lg`；保留 `--radius` / `--radius-sm` 兼容别名 |
| 层级阶 | `--ui-z-base/sticky/drawer/overlay/toast`（取代 `z-index: 9999` 那类魔数） |
| 阴影 | 新增 `--ui-shadow-sm`；并写明**只给浮层用**，平铺卡片靠边框与留白分层 |
| 排版 | `--ui-font-sans` / `--ui-font-mono` 成为**有意的系统栈**，并写明为什么这么排 |
| 数字对齐 | `.ui-num` 与 `code/kbd/samp` 统一 `tabular-nums` |

**顺带修掉两处既有问题**（核对着 token 引用发现的）：

1. `font-family: Inter, …` —— `ui/` 下**没有任何字体文件**，也没有 CDN 引用，所以 Inter
   谁也没提供，实际渲染成 Segoe UI。**写了等于没写**，而且让人以为界面在用 Inter。
2. `app.css` 有一处 `color: var(--ui-text-muted)` —— **这个令牌根本不存在**，
   声明被浏览器整条忽略，颜色退化成继承。已改为 `var(--ui-muted)`。

**核对手段**（可复用）：扫出所有 `var(--foo)` 引用与所有 `--foo:` 定义，做集合差。
本次结果：**全部已定义**；写死的 `Consolas` 剩 0 处。

**验证**：tsc / 49 项前端测试 / vite build / `cargo build -p aivc-app` 全绿；
重跑基线集到 `shots/after-tokens/`，**五张全部变化**（字体栈与等宽栈替换所致）。

> **这一轮没有肉眼看过渲染结果** —— 变化幅度由哈希差异确认、成因已完全解释，
> 但真正的视觉判断要留到**下一轮改动布局时**做，那时差异是结构性的。

**字体方案仍未定**：本轮把字体栈做成**有意的系统栈**（零体积、无网络依赖），
把「换字体的成本」压到只改 `--ui-font-sans` / `--ui-font-mono` 两个令牌。
若之后决定内置 Geist，改这两行即可，不必碰任何组件。
