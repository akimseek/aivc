## A0. 🔴 实际使用中发现的两个缺陷（第 51 轮，用户跑 `aivc-app.exe` 后报的）

**这两条优先级最高**：它们不是「文档里推理出来的」，而是**真的用起来就撞上**的。
其余各组都排在它们后面。

### H1. 回车键会打开新终端会话

**现象（用户原话）**：「进入终端会话后，提示需要更新，按回车键居然会打开新终端会话」。

**已核对过的事实**：

| 查了什么 | 结果 |
| --- | --- |
| 界面里有没有「需要更新」这个提示 | **没有**。唯一的 `更新 …` 文案是 `app.tsx:839` 的**会话更新时间**（`更新 {formatWhen(updatedAt)}`）。所以那不是升级提示，是个时间戳——**用户把它读成了升级提示，这本身也是个文案问题** |
| 有没有全局键盘监听 | 有，`app.tsx:74-83` 在 `window` 上监听 `keydown`，但**只处理 Ctrl/⌘+K**，不处理裸回车 |
| 有没有 `<form>` / `onSubmit` / `autoFocus` | **一个都没有**。所以「回车触发某个默认动作」这条常见机制**不成立** |
| 终端输入怎么走 | `terminal-pane.tsx:77` 的 `term.onData → terminal:write`，是正常的 PTY 通路 |

**因此界面代码里没有直接原因**，剩下的最强假设是**命令面板开着**：
`command-palette.tsx:99` 的回车执行当前项，而**第一项就是「新建 Codex 终端」**
（`app.tsx:233`）。也就是说「回车 → 新终端」与「面板第一项」完全吻合。

**要确认的事**：出现这个现象时，屏幕上**有没有一个命令面板/搜索列表**？
以及它是怎么被打开的（是不是按过 Ctrl+K，或者点过什么）。

### H2. 点历史会话**没经过「选平台/目标」那一步**就直接进了终端

> **⚠️ 第 58 轮更正**：这条原先被我写成「点会话直接进终端，而旧平台进详情」，
> **结论是反的**。用户纠正：**点左侧历史会话就是进终端；详情只是终端会话的子功能。**
> 所以问题**不在**「进了终端」，而在**「进终端之前少了那一步对话框」**。

**现象（用户原话）**：「**默认不选择平台、目标**，选中后直接进入终端会话，
而终端会话的详情才是加载/从此处分支的」。

**正确的差异**：

| | 旧平台 | aivc-rs |
| --- | --- | --- |
| 点历史会话 | 进终端 | **也进终端** —— 一致 |
| 进之前 | **对话框**：工作目录 / 标题 / 提示词 / CLI 参数（恢复历史时「设置工作目录 → 继续打开」） | **没有这一步** 🔴 |
| 会话详情 | 终端会话的**子功能**（时间线 / 加载更早消息 / 从此处分支） | **没有对应物** 🔴 |

**修复**：主要是 **M2（新建/恢复会话对话框）**，其次 M1（详情子视图）。

## B. 有意的行为差异（**不是缺口**，列在此处是为了不再被反复提起）

| 差异 | 位置 | 为什么保留 |
| --- | --- | --- |
| 超时按**每次尝试**计时且可重试（老平台是整轮共享一个预算、超时即终止） | §23 | 老平台的超时**不转移**：一台卡住的上游会把整次请求耗光然后放弃，故障转移形同不存在。Rust 会放弃卡住的那家转给下一家 |
| 「没有可用供应商」记为**失败**（老平台记为成功） | §37 | 请求一条都没发出去却记成成功，会让用量报表失真 |
| 「路由不存在 / 鉴权失败」**保持 `ok`** 但补 `errorCode` | §39 | 那不是供应商的错，记成失败会污染按供应商统计的失败率与熔断判定 |
| 查询执行器**不跟随重定向**（老平台的 `fetch` 跟随） | §24 | 跟随会把**供应商密钥**发给重定向目标；不跟随的代价是正当重定向会让查询失败。两种取舍各能解决对方解决不了的场景，**没有依据判断哪个更重要，因此不改** |
| 健康状态**启动时读回一次**（老平台每个请求前读回） | §29.3 | 每请求 hydrate 会把内存里的失败窗口清掉，使「窗口内 N 次失败」的判定失效 |
| 网关**自接管** `accept-encoding` | §21 | 其 HTTP 客户端不解压；上游一旦压缩，失败转移规则与用量统计会**静默失效** |
| Claude 的路由走 `--settings` 而不是只靠环境变量 | §31.5 | 它的 `settings.json` 里的 `env` 块**覆盖进程环境**，只注入环境变量时网关会被**静默绕过** |
