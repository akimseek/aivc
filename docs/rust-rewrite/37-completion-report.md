**拆分过程中被探针抓到、并修掉的真实缺陷**（这是抽组件最容易引入的一类错）：

```
closeTab 里把「取 terminalId」写进了 setTabs 的更新函数：
  let closingTerminalId;
  setTabs((current) => { closingTerminalId = current.find(...)?.terminalId; ... });
  if (closingTerminalId) void closeTerminal(closingTerminalId);   // ← 永远是 undefined
```

React **不保证同步调用更新函数**，于是 `closeTerminal` 从未被调用：标签消失了，
终端进程还活着、xterm 还挂在 DOM 上。探针读数直接暴露了它：
退出后 `xterms` 应该是 0、实际是 1，而且每开关一次就多一个。

**我还在中途写坏了两个草稿，并自己删掉了**：
- 一个 `app-overlays.tsx` 里给 `onCopyId` / `onRemove` 填了 `() => undefined` 占位
  （复制与删除会**静默失效**），另有一个 `{void x}` 垃圾语句 —— 整份删除重写；
- 重写时最终版的 `OverlaysActions` 里**每一项都是必填的**，漏接会被类型检查挡住。

## 七、追加一轮（用户确认后继续）

### 7.1 修「供应商没有模型厂商的选择」（用户报告）

**根因**：`VendorsPanel` 保存时用的是**外层的** `providerId`（侧栏当前平台），
而界面上**没有任何地方能改它**。旧平台的表单有一组「模型厂商」按钮
（`vendor-manager-dialog.tsx` L452-465）。

**修法**（照旧平台，并且把列表也一起对齐）：

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 表单的模型厂商 | 无，保存时被当前平台覆盖 | 一组厂商按钮，**保存用的是草稿里的厂商** |
| 列表范围 | 只有当前平台 | **全部平台**（`vendor:list` 不带 `providerId` 时后端列全部） |
| 平台筛选 | 无 | 「全部平台」+ 各厂商 |
| 厂商列 | 无 | 有，显示**平台名**而不是编号 |
| 空状态 | 「这个平台还没有配置供应商」 | 按筛选说清是「这个平台没有」还是「一个都没有」 |

**测试钉住的第一条**就是那个缺陷本身：改了厂商之后 `vendor:save` 收到的
`providerId` 必须是改后的那一个，**且不等于外层的当前平台**——
两者不同才说明真的用了草稿里的值。

### 7.2 复核三个面板的「有数据」渲染（19/19 通过）

上一轮验收时运行根里一条网关记录都没有，三张表走的**全是空状态**。
空状态与有数据是两条代码路径。要让面板里真的有数据只有两条路：
让网关真的服务一次请求（要配供应商、且花用户的钱），或往库里写符合真实 schema 的记录。

这里走第二条，做法与工具都留下了：
`scripts/seed-gateway-logs.cjs`（造数据）+ `scripts/probes/gateway-panels-data.js`（验收）。
**它与「伪造验证结果」是两回事**：写进去的是数据，而面板要从这份数据里算出什么、
有没有算对，是应用自己算的。因此它能证明渲染路径，
**证明不了「网关记账逻辑对不对」**——后者要看 Rust 侧单测与真实请求。

**为什么要求库已经存在**：表结构由应用自己的迁移建立。手写一份 `CREATE TABLE`
等于把 schema 抄了第二遍，抄错一处以后就再也对不上。所以脚本拒绝自行建表，
而是先跑一次空探针（`probes/_boot-only.js`）让应用把库建出来。

19 项断言里有代表的几条：

| 断言 | 它证明什么 |
| --- | --- |
| 平均耗时 `8041 ms` | 是**平均**不是求和（求和是 32163） |
| 总 token `1.7k`、费用 `$0.0123` | `usage_json` **真的被解析出来了** |
| 按供应商分组显示「供应商甲/乙」 | 分组维度真的分开了，且查得到供应商名 |
| 异常里有 `rate_limited` / `HTTP 429` / `30000 ms` | 错误代码与上游状态都渲染 |
| **日志里有 `route-missing`** | 最要紧的一条：`outcome=ok` 但带错误代码的记录也显示得出来 |

**这一轮暴露的两个我自己的错**（都是断言写错，不是代码错）：

1. `usage_json` 我按 **snake_case** 写，而 `GatewayUsage` 带
   `#[serde(rename_all = "camelCase")]` —— 写成 snake_case **不会报错**，
   会解析成功但每个字段都是 `None`，面板上 token 显示成「—」。
   这是静默出错，只有真的看一眼才发现。
2. 用量表的供应商列我没注意它显示的是**展示名**：供应商不在表里时走
   `已删除供应商` 占位（后端的 `DELETED_VENDOR_LABEL`），真身份在 `title` 上。
   我第一版断言「表里应能看到 `seed-vendor-a`」因此误报。
   修法是**让运行根更真实**（把两家供应商也登记进去），
   并把断言改成「占位文案只出现一次」——那条 `(none)` 供应商的记录确实不存在，
   它走占位是对的。
