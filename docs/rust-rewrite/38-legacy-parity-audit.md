# 旧平台对齐审计（第一次穷尽比对）

> 起因：用户问「除了 5.5，功能已经对齐旧平台了吗」。
> 我答不上来——`36-comprehensive-gap-list.md` 是**我自己筛过的 44 行**，
> 依据是 17 张截图加浏览过的源码，**不是把旧平台前端逐个过一遍**。
> 这份文档就是那次比对的结果。

---

## 1. 做法

`scripts/audit-legacy-strings.cjs`：

1. 抽出旧平台前端（`src/renderer/src`，**100 个文件**）里**用户可见的中文串**——
   JSX 文本、`label=` / `title=` / `placeholder=` / `aria-label=` 的值、字符串字面量；
2. 逐个到新平台源码（`ui/src`，73 个文件）里找；
3. 找不到的按**来源文件**分组（分类时要靠上下文判断），写到
   `scripts/legacy-strings-missing.txt`。

**结果：旧平台 537 条可见文案，其中 305 条在新平台源码里找不到。**

## 2. 这个脚本测不了什么（必须先说）

| 测不了 | 例子 |
| --- | --- |
| **行为** | 同一个词可能在新平台上做的是另一件事 |
| **「字符串在、功能不在」** | 系统终端类型选择：新平台**压根没有那几个词**，脚本看不见 |
| **旧平台自己写错的文案** | 命令清单写着 `codex resume <id>`，而后端实际生成的是 `--resume <id>` |

因此第 3 节里的每一条**都另外对照了源代码行为**，不是只看字符串。

| A8 | 会话/用量的 **usage 明细**（缓存输入 / 总量 / 无 usage 数据…） | 旧平台 `session-format.ts` 有；用量面板搜「缓存 / cached」= 0 | 纯前端 |

### 3.1 A4 展开：这不只是「少一个输入框」

后端把「供应商」和「写进 CLI 的那份配置」分成两层：

| 命令 | 做什么 |
| --- | --- |
| `vendor:save` | 存应用数据库里的记录（含 `configs` 模板列表） |
| `vendor:set-enabled` | **只翻数据库里的启用标志位** |
| `vendor:enable` | **把启用的模板写进用户的 CLI 配置文件**（写前备份到 `data/vendor-backups/`），且校验「请至少启用一个配置文件」 |

**我的界面用的是 `vendor:set-enabled`，而且从不设 `configs`。** 后果：

1. 供应商能被「启用」，但**CLI 的配置文件从来没被写过**；
2. 我的面板里却写着「写入 CLI 配置前会自动备份到 `data/vendor-backups/`」
   ——**这是一句我做不到的承诺**，本身就是个缺陷；
3. 用户**无法**让 CLI 在**不走网关**的情况下直接用某个供应商（旧平台可以）。

要判断的是：这到底是「**有意改了模型**」（我的实现让网关在终端启动时注入凭据，
因此不需要写 CLI 配置），还是「**漏接了**」。

我倾向于是**前者有意的**（网关注入是更干净的做法，也避免改动用户的 CLI 配置），
但**这一条必须由用户定**，因为它改变了「供应商」这个概念的含义。
**无论怎么定，界面那句备份提示现在都是错的。**
| A11 | **终端输入模式切换**（切到终端原生输入 / 切回自管输入） | 旧平台状态栏有这两个按钮；我只有「第一段输出时自动显示」 | 纯前端 |
| A12 | 网关地址相关的引导文案（请先开启本地 Gateway / 请先生成访问令牌 / 未运行） | 我做了 `baseUrl`，但缺「没开启时该做什么」的引导 | 纯前端 |

## 4. 结论：对齐了吗

**没有。** 44 条那份清单（第 10–12 节）说的是「那份清单做完了」，
而不是「功能对齐了」。两者的差别就是这份文档。

按量级：**真缺功能 12 项**、**操作反馈系统性缺失约 70 条文案**、
其余约 100 条是措辞或工程差异。

### 6.1 顺带挖出并修掉一个后端缺陷：费率校验拒绝 0.55

`normalize_rate` 用的是**精确浮点相等**：

```rust
let scaled = value * 100.0;
if scaled.round() != scaled { return Err(PricingInvalid { label }); }
```

而 `0.55 * 100.0` 在 IEEE 754 里是 `55.00000000000001`，于是 **`0.55`、`2.2` 这类最常见的
价格直接被拒**，报的还是「必须是非负数，且最多保留 2 位小数」——用户看着 `0.55`
完全不知道哪里错了。

**这个缺陷是探针撞出来的**：我给探针写了一个 `inputPerMillionUsd: 0.55` 的供应商，
第一次跑就抛在 `vendor:save` 上。

**它为什么一直没被发现**：原有的测试用的是 `1.25`，而 `1.25` 恰好能被二进制精确表示
（`1.25 * 100.0 == 125.0`）——**那个测试在缺陷存在时也是绿的**。

**改法**：改成带 `1e-9` 容差的比较。原注释担心「用误差比较会让 1.234 被误判为合法」，
但按量级那个担心不成立：`1.234 * 100.0 = 123.4`，与最近整数差 `0.4`，远大于 `1e-9`。
新增两条测试：常见价格必须被接受、真实三位小数仍然要拒。

界面侧的 `parsePrice` 从一开始就带容差，并补上「最多 2 位小数」这一条——免得同一个坑踩两次。

### 6.2 一处需要记录的契约不对称

实测确认：`vendor:save` **省略 `pricing` / 高级 JSON 就是清空**（PUT 语义），
而 `apiKey` 留空表示**沿用旧值**（后端文档里写明的例外）。

两者不对称。我的界面不受影响，因为**编辑时会把值回填进表单**，提交时一定带着它们
（探针专门验了这条路径）。但这条不对称值得记下来：将来别的调用方
（脚本、导入）漏传一个字段就会**静默清掉**用户的费率。

### 6.3 本轮又抓到自己写的两个空过断言 + 两个探针自身的毛病

| 问题 | 表现 |
| --- | --- |
| **否定断言空过** | A4 那条 `!text.includes("自动备份到")` 在**面板没打开**时也成立——探针找的菜单项叫「供应商管理」而不是「供应商」，压根没打开面板。加了一条正向守卫（确认页面上有「新增供应商」）才堵住 |
| **守卫自己写错** | 上面那条守卫第一版用「模型厂商」判断，而它只在**编辑表单打开时**才存在，于是仍然失败——判据要选页面上常驻的东西 |
| **探针漏了 `id`** | 重新写回供应商时没带 `id`，撞上「供应商名称已存在」的唯一约束，把探针自己的流程打断了 |
| **探针不留垃圾** | 中途失败会留下同名供应商，下一次跑必撞唯一约束。现在**开头先清理**同名残留 |

**这是本轮第三次**抓到自己写的空过断言（前两次：`includes("存在")` 命中了表头「存在性」、
`includes("自动分配")` 命中了另一个提示）。共同形状都是**断言的字面在别处也存在**。

## 9. 第四批量落地结果：操作结果反馈

**做法上先查清了一件事**：失败反馈**已经有了**——`state.error` 渲染在状态栏
（`<span className="err">`）。所以 C 类里那约 25 条「失败文案」其实属于措辞差异（B 类），
**真正缺的是成功反馈**。

### 9.1 收敛成一个通知通道，而不是在十几个组件里散撒 toast

| 层 | 谁在报 |
| --- | --- |
| `useConsole({ notify })` | **会话与设置**类动作（改名 / 复制 / 删除 / 恢复 / 收藏 / 分支 / WSL 目录） |
| `ConfigOverlay` 的 `onNotify` → 各面板 | **供应商 / 技能 / 环境 / 网关** |

于是「做完一件事要说一声」只有一处实现。`useConsole` 内部用 **ref** 持有回调、
对外暴露恒等稳定的 `notify`——否则十几个 `useCallback` 的依赖数组都要记得加，
**漏一个就是「这个动作不报」，而且不会报错**。

### 9.2 补齐的动作（每条都带上是哪一个）

| 区域 | 动作 |
| --- | --- |
| 会话 | 改名、复制、移入回收站、彻底删除、恢复（单条 / 批量）、收藏 / 取消收藏、创建分支 |
| 设置 | WSL Codex 目录已保存、已恢复自动探测 |
| 供应商 | 新增、保存、启用 / 禁用、删除 |
| 技能 | 导入、启用 / 禁用、恢复、彻底删除 |
| 环境 | CLI 安装完成 |
| 网关 | 启用 / 关闭本地网关、保存端口、故障规则保存、外部 API 启用 / 关闭、令牌轮换 |

几处措辞是**刻意带上对象**的：`供应商已删除：<名称>`、`Skill 已禁用：<名称>`。
批量操作报条数（`移入回收站完成：共 N 条。`）。都是因为「做完之后列表变了，
用户可能记不清自己做没做、做的是哪一条」。

### 9.3 测试抓到的一处用词不一致

我写的按钮文案是「停用」而提示是「已禁用」——**同一件事在界面上有两个名字**。
旧平台按钮写的就是「禁用」（`skill-manager-dialog.tsx`），提示也是「Skill 已禁用。」。
改成一致后，测试从「期望停用」改成「期望禁用」。

这一条之所以被发现，是因为测试断言的是「提示里要出现那个动作的词」，
而不是只断言「onNotify 被调用过」。

### 9.4 探针：真的在界面上看见那句话

`scripts/probes/action-feedback.js` **9/9**。单测只能证明「`onNotify` 被调了」，
而从 `notify` 到**用户看得见的那条提示**隔着三层（属性传递 / `useToast` 的计时器 /
`AppOverlays` 里的条件渲染）。因此判据是：

- 触发一个真实动作 → 在 DOM 里找那句话；
- **先确认提示原本不在**（否则「出现了」不算数）；
- 两条通道各验一次：`useConsole` 那条（收藏）与 `ConfigOverlay` 那条（删供应商）；
- 再验它**几秒后自己消失**（不会一直压着正文）。

## 11. 第二批量落地结果：故障规则的两半

### 11.1 A1 自定义返回——又是「后端早就发、界面没接」

前端 `FailoverRule` 类型与 `saveFailoverRule` **早就收了**
`customResponseStatus` / `customResponseBody`，后端 `NormalizedFailoverRule` 也一直在存，
**只是表单没有输入框**。这一批补的是表单与四条校验：

| 校验（照旧平台） |
| --- |
| 自定义返回状态码需为 100 到 599 之间的整数。 |
| 自定义返回内容必须是合法 JSON。 |
| 自定义返回内容不能超过 32 KB。 |
| 自定义返回状态码和内容必须同时配置。 |

**32 KB 按字节算**（`TextEncoder`），不按字符数：一个中文字符占三字节，按字符数
会放过三倍的量。测试里专门有一条用 11000 个中文字符（字符数没超、字节数超了）来钉它。

编辑时**必须回填**这两项——不回填的话点一次「保存修改」就会把它们清掉。
这与第一批量里供应商费率是**同一个坑**，因此这次直接写进注释与测试。

### 11.2 A2 试规则——新加一条命令，而不是在前端重写匹配

匹配规则是「状态码精确匹配 **或** 错误文本不区分大小写包含匹配」。这件事只有
规则引擎自己说了算。若让界面自己实现一遍，两份逻辑迟早分叉，表现是
**「测试说会命中、实际没切换」**——那是最难查的一类偏差。

因此：

1. 把匹配抽成 core 里的自由函数 `match_rule`，返回 `Option<RuleHit>`
   （`Status` / `Pattern`）——原 `FailoverRule::matches` 改为调它；
2. 新增命令 `gateway:test-failover-rule`，**调用同一份 `match_rule`**；
3. 加了一条测试 `the_forwarding_path_and_the_test_command_agree`，
   用六组输入断言两条路结果一致——**这条测试才是「同源」的凭据**。

返回 `matchedBy` 而不是只回布尔值：用户看到「没命中」需要知道该改状态码还是改文本。

**命令面从 90 条变成 91 条**（Gateway 域 19 → 20），计数断言与路由契约同步更新。
`dispatch` 因此超出 clippy 的 150 行上限，把四个同构的规则分支抽成了
`dispatch_failover_rules`。

## 12. 第三批量落地结果：观测面

### 12.1 A9 自定义日期区间——纯逻辑层早就写好了，只是被过滤掉

`gateway-range.ts` 里**早就有** `customBounds`，`USAGE_RANGES` 里**早就有** `custom`——
而三个面板都写着 `USAGE_RANGES.filter((item) => item.key !== "custom")`，
把这个选项直接丢掉了。补的是接线。

**这里我改了一个自己早先的决定**：`customBounds` 遇到起止颠倒时原来**静默交换**两端。
改成**报错**，两个理由：

1. 静默重排用户输入会让他从此不知道自己填的到底被怎么理解了；
2. 旧平台本来就是报错（`起始日期不能晚于结束日期。`），不必另创语义。

顺带把结果类型从 `{start,end} | null` 改成**带原因**的判别联合，因为旧平台有**两条**

合成一处之后，测一遍等于三处都测了。

### 12.2 A8 usage 明细——又是「类型里有、界面没显示」

前端 `UsageDimension` / `UsageSummary` **一直有** `cachedInputTokens` / `reasoningTokens`，
表格与总览只显示了 `总 token`。现在总览给出 输入 / 输出 / **缓存输入** / 推理 / 总 token / 费用，
维度表加了输入 / 输出 / 缓存输入三列。

「缓存输入」值得单独一个格子：它通常是**便宜很多**的那一部分，
因此「总数多少」不如「其中多少是缓存的」有用。

### 12.3 A10 日志模式——**有意不做**，而且删掉了一条会误导人的声明

旧平台的「仅文件日志 / 仅请求记录 / 文件日志和请求记录」是为区分**两份**记录而存在的：
`logs/gateway.log`（+ 轮转 `.1`，单文件 2 MB）与数据库里的请求记录。

**本工程的 `gateway.log` 根本不存在。** 全仓搜 `gateway.log` 只有 8 处命中，
全部是文档、一个访问器、以及它的测试——**没有任何写入方**。
实际存在的只有 `logs/app.log` 与 `logs/performance.log`。

而 `paths.rs` 的模块文档与 `logging/mod.rs` 都在宣称它存在（还写着不存在的轮转），
`AppPaths::gateway_log_path()` 是一个**指向永远不会出现的文件的访问器**。
留着它是个陷阱：以后有人会读它、清它，拿到空结果，然后得出「没有网关日志」的结论。

**处理**：
1. 删掉 `gateway_log_path()`；
2. 两处文档改成说明「本工程不写那份文本日志」以及**为什么**；
3. 界面上**不加**「日志模式」这一项——加了就等于承认有个并不存在的文件日志。

**为什么不做而不是补上**：两份记录的内容完全重合，而请求记录**可查询**
（按平台/供应商/结果/时间过滤、分页、聚合用量），文本文件做不到。
再写一份轮转文本日志，只是为了给「清理文件日志」这个选项一个对象——
那是把旧工程的实现形状当成了需求。

**这是一处有意的功能差异，需要你知道。** 如果你要的是「把日志导出到文件以便外部查看」
（旧平台的文本日志顺带满足的另一个用途），那是另一件事，说一声我加一个**导出**动作，
那比再维护一份轮转文本日志干净得多。

### 12.4 A12 网关未运行时的引导

地址为空时不再只说「没有在监听」，而是按停在哪一步给不同的指引：
没开启就让他开，开着没监听就让他重启。外部 API 那段也补了一句**半配置状态**的说明
——「开着但没有令牌」时请求会被全部拒绝，而界面上只看得出「开着」。

### 12.5 顺带修掉一处「同一个文件名两处真值」

`ProviderContext::performance_log_path()` 自己 `join("performance.log")`，
而它上面那个方法就是委托给 `AppPaths` 的。改成委托——
同一个文件名有两处真值，改目录结构时必漏一处。

## 15. 第六批量：A4 落地、启动默认、终端区动作条

### 15.1 A4 供应商启用改为写 CLI 配置

按用户决定：**启用要写 CLI 配置，新建默认不启用**。

- 停用 → `vendor:set-enabled`（只翻启用位，**不动用户的文件**）；
- 启用 → `vendor:enable`（写文件 + 备份，**先写文件再改数据库**）；
- 新建 → `enabled: false`（启用会写用户的 `~/.codex/...`，不该由「新增」顺手完成）；
- 启用成功后的提示点名**写了哪些文件、备份在哪**。

配套：`vendor:save` 在调用方**没提 `configs`** 时兜底填平台默认模板
（`aivc_tooling::vendor::default_vendor_configs`），否则启用必然失败，
而报错（`请至少启用一个配置文件。`）指向一个用户没有的概念。
显式传 `configs`（含空数组）一律尊重调用方。

`default_config_targets` 是新的**一处真值**（此前路径只隐含在各 provider 的私有
`default_config_dir()` 里、内容按后缀匹配在 `default_config_content` 里），
并加了测试钉住「每条目标路径都有对应模板」——两条清单漂移的后果是
启用时报「配置文件内容为空，已中止写入」，而用户看不懂。

**顺带修掉一个真缺陷**：备份路径重复了一层
（`data/vendor-backups/vendor-backups/<供应商名>/<时间戳>/`）。
`ctx.vendor_backup_root()` 已返回 `data/vendor-backups`，而
`tooling::backup_root(base, …)` 会再拼一层 `vendor-backups`。现在传 `data/`。

全量测试（约 670 条）跑完，用户那两个文件的时间戳不变——已验证。

### 15.6 一处必须记下的副作用

`startup-and-detail.js` 走「点会话行 → 恢复会话 → 启动终端」，
因此它**会真的启动 Codex CLI**：消耗用户额度，且 Codex 自己会写
`~/.codex/config.toml`（实测多出一段 `[tui] screen_reader_detection_done = true`）。
这条探针不宜反复跑。

## 16. 这份审计本身的局限

- **只看 `src/renderer/src`**。旧平台的 main 进程、preload、共享常量**没有扫**。
- **只抽中文串**。纯英文/符号的界面元素（图标按钮、`aria` 名称、快捷键）会漏。
  **`aria-label` 我抽了**，但只抽了带中文的那些。
- **`ui/src` 之外的资产没比对**：样式类名、快捷键绑定、窗口行为。
- **只证明「旧平台有、新平台没有」这一个方向**。反过来（新平台有而旧平台没有）
  没查——但那个方向不影响「对齐」这个结论。
- 因此 **12 项是「至少 12 项」**，不是「恰好 12 项」。

## 7. 与 `36-comprehensive-gap-list.md` 的关系

那 44 条与这 12 项**几乎没有重叠**（只有 5.5 的诊断页相关）。原因：

- 那份清单是**按界面逐页看**得出的（17 张截图 × 浏览源码），
  它擅长发现「某一页缺了什么」；
- 这份审计是**按文案穷举**得出的，它擅长发现「某个动作少了回应」——
  而后者恰恰是 C 类那 70 条，也是前者**完全看不见**的一类。

两份文档不互相替代：一份是产品视角的清单，一份是机械化比对的候选集。
